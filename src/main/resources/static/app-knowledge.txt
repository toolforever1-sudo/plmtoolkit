PLM Toolkit — Application Knowledge Base
Last updated: June 5, 2026

OVERVIEW:
PLM Toolkit is a web-based tool for exploring Agile PLM data at SanDisk. The top navigation has been consolidated into parent tabs:
  - Items (parent) → Field Changes / Part Extract / Agile Lookup / SKU Lookup
  - BOM (parent) → Explorer / Compare
  - Change History · ECN Dashboard · Shop-Floor Docs
  - More\u2026 (parent) → Work Instructions / User Management / Extensions / Data Compare / Change Reviews
  - Admin-only top-level: Utilities · 🧪 Labs
The 🧪 Labs tab (admin-only, has a small "Admin" red badge after the label) groups three admin tools as sub-tabs: ⚡ BOM Race · 📊 AD Health · 🤖 AI Eval. AD Health and AI Eval used to be standalone top-level admin tabs and Admin-dropdown links — they moved into Labs on May 10, 2026 alongside the new BOM Race showcase.
There is also a standalone Debug Assistant page (admin-only, accessible via the "Debug" link in the Help dropdown). Users log in with AD credentials and must be in the IT-APP-Agile-admin group. The tool is currently in beta.

ADMIN DROPDOWN (slimmed May 10, 2026): now contains only operational actions — ⚠ Maintenance and 👥 User Management. Plugin Guide moved to the Help dropdown. AD Health, AI Eval, and BOM Race are reachable through the Labs tab (sub-tabs of Labs), not the Admin dropdown.

NAV NOTE: when a user says "BOM Explorer tab" or "Part Extract tab", they mean a sub-tab inside the parent. Both naming styles work — "Items → Part Extract" and "Part Extract" point at the same panel. "User Permissions" still resolves to the User Management tab (renamed May 6, 2026). "AD Health" and "AI Eval" still resolve to the right screen even though they are now Labs sub-tabs — both `switchTab('adhealth')` and `switchTab('aieval')` continue to work and land inside Labs.

ACCESS & LOGIN:
- Login with Windows/AD username (without domain) and password
- Must be member of IT-APP-Agile-admin Active Directory group
- If not in the group, an access request form appears — fill it out with a justification
- Admin team is notified by email and adds you to the group
- Within 10 minutes of being added, you receive an "Access Granted" email
- Sessions expire after 30 minutes of inactivity — you'll be redirected to login
- A countdown timer in the header shows the remaining session time
- If you see "undefined" in results, your session expired — refresh and log in again

TABS VISIBILITY:
- Visible to everyone: Items (parent → Field Changes / Part Extract / Agile Lookup / SKU Lookup), BOM (parent → Explorer / Compare), Change History, Data Compare, Change Reviews. Each Items child and each BOM child is independently grantable in User Management — admins can hide an individual sub-tab from a user; the sub-tab button itself disappears for them.
- Utilities (formerly Reports): visible to admins AND non-admins listed in a utility's allowedUsers
- Extensions: admins, plus non-admins who have been granted "Extension Contributor" by an admin (contributors see all sources but only get Add+Generate; cannot Remove or Schedule)
- 🧪 Labs (parent, admin-only — IT-APP-Agile-admin group): contains three sub-tabs:
    - ⚡ BOM Race (admin-only) — head-to-head benchmark of toolkit cached SQL vs live Agile SDK BOM explode
    - 📊 AD Health (admin-only, pdl-plm-admin) — LDAP / Active Directory connectivity test
    - 🤖 AI Eval (admin-only, pdl-plm-admin) — chatbot quiz harness with persona-driven Tester + LLM Evaluator
- ECN Dashboard (formerly "ECN Report"): visible to everyone (admins additionally get edit, email, SLA-upload, and editor-management buttons)
- Shop-Floor Docs: visible to everyone by default (admins can hide per-user via User Management). Replaces the legacy nightly SDSM batch — operator types/scans a part number, sees the controlled PDFs (WI / VIC / Drawing / Quality Notice) tied to its latest released revision, and previews them inline. No admin role gate; same data is live from agprod that the legacy job would have shipped to the Penang MES the next morning.
- Work Instructions (formerly "Help Center"): visible to everyone (search across uploaded PPTX/PDF/XLSX/DOCX/TXT documents; admins additionally get the upload drop-zone)
- Debug Assistant: admin-only (separate page at /debug.html, linked from the "Debug" link in the Help dropdown)

- "Disposition" / "Change disposition" / "Change Status": Agile lifecycle state of a change order. Typical values: In Review, Awaiting Approval, Released, Cancelled, On Hold. Surfaced in the Change History tab as the "Change Status" column. Anything visible in Change Reviews (Queue or Dashboard) is by definition NOT yet Released (i.e. still open / in review)
- "Open" change / "open ECN" / "still open": any change that hasn't been Released yet. Every row visible in Change Reviews is open by definition (Released changes drop out automatically). To see only the most stale opens, use the "Stale >10d" quick-filter chip in Queue mode, or sort the Dashboard's Aging bar chart
- "Manufacturing change" / "manufacturing-impacting change" / "MFG change": typically MCO (Manufacturing Change Order) change type. In Change Reviews → Dashboard mode, the "By Change Type" pie chart shows the MCO breakdown; click the MCO slice (or use the Change Type filter on KPI tiles) to narrow. For a specific quarter, set Lookback to 90 days first

- "Shop-Floor Docs" / "shop floor docs" / "SDSM" / "SDSM tab" / "shop floor lookup" / "operator docs" / "controlled docs for a part" / "drawings for this part" / "VIC for a part" / "work instructions for this part" / "Quality Notice for this part": this is the Shop-Floor Docs tab. Operator types or scans a part number to see every controlled PDF (WI / VIC / Drawing / Guideline / Checklist / FPS / VAR / Quality Notice) tied to that part's latest released DCO/ECO. Replaces the legacy SDSM nightly batch (~/documents/sdsm/call_run.bat). DO NOT confuse with Work Instructions tab — that one searches uploaded PPTX/PDF/DOCX knowledge documents (general PLM team library), while Shop-Floor Docs returns Agile-managed controlled documents tied to a specific part revision

Each banner row lists the deviation number, description, and through-date. Filter is "Status = Executed" + "Workflow = Quality Notice Workflow" + Effective From ≤ today ≤ Effective To
- "eVAR" / "Camstar eVAR" / "OOB icon": the manufacturing-execution system at the SanDisk Penang factory that auto-displays controlled docs to operators at ONLINE stations when they scan a serial number. Driven by Document Style + (Product Group, Product, Spec) matching on Page Three. The Shop-Floor Docs tab is the LIVE equivalent — same matching logic, same source data, but no overnight ETL lag. Reference: training guide 27-04-SM-02-00054 ("eVAR and Offline Document Training Guidelines")
- "TTMS" / "WDSM Portal" / "SSD TTMS e-Learning" / "offline document": the training-management system for OFFLINE stations (where Camstar isn't running). Same Page Three matching as eVAR plus an extra (Operation, Work Center) layer. Document Style values for TTMS-only docs are "Offline VAR" and "Offline WI" (vs eVAR's WI / VAR / VIC / FPS / Guideline / Checklist / Drawing / Temp VAR). The Shop-Floor Docs tab includes both sets — Offline-* docs render with a purple badge to distinguish them from the eVAR (online) set
- "ETL lag" / "next-day display" / "doc owner says it's released but operator can't see it": legacy eVAR/TTMS pulls from Agile via daily ETL — Agile export at 6am, integration at 9am, Camstar transfer at 6pm, display by 8pm. So a DCO implemented mid-morning shows up on the floor that evening at the earliest. The Shop-Floor Docs tab in the toolkit cuts this out — query is live against agprod
- "ALL conflict" / "doc not showing" / "configured everything but doc still doesn't display": the eVAR rule is that on Page Three, if you set Product / Product Group / Spec to 'ALL', you can't ALSO list specific values in the same field. Mixing them silently breaks display. The Shop-Floor Docs "Why?" auto-diagnostic (fires on empty results) calls this out as an "'ALL' conflict" check with FAIL status. Reference: training guide page 22
- "IMS Dashboard" / "IMS Review" / "ims review" / "ims dashboard" / "yearly review" / "annual document review" / "DRR review" / "document review" / "DRR Dashboard" / "review tracker" (CAUTION — also a separate tab name): the IMS Dashboard tab (TAB 17 below — renamed from "IMS Review" on 2026-06-04 per Jimmy\'s request; the underlying activity log event names still use IMS_REVIEW_* for backwards compat). Driven by Page Three.Next Review Date on IMS documents. Toolkit fans out the Send → DO → DM cascade automatically and writes signed attestation PDFs back to the DRR / DCO. NOT to be confused with "Review Tracker" tab, which is the org-wide doc-review queue.

Mirrors the weekly Excel "Agile PLM IT Enhancements Status Report" as a live grid against agprod (sub-second load, ~90 rows). All 7 IT-owned cells are inline-editable (IT Owner, Hrs, Project, IT Actions Taken, Target UAT, Target Go-Live, IT Log) as of 2026-06-12; saves go to Agile under the user's own AD identity via a transient SDK session (NOT Administrator) so the change History attributes the edit to the real person. Auto-grants to the PDL-PLM-admin AD group + per-user grants via User Management. Three sub-tabs (2026-06-15): All Enhancements · My Enhancements · Meeting Mode.
- "Meeting Mode" / "meeting mode" / "weekly meeting" / "backlog review" / "IT meeting" / "IT review meeting" / "review the backlog with the room" / "consolidated emails after meeting": Meeting Mode sub-tab on the IT Enhancements page (third pill in the sub-nav, shipped 2026-06-15). Walk the IT-Enhancement backlog with the room — multi-requestor select → focus pills (Overdue UAT/Go-Live · Going live ≤7d · High priority no IT owner) → list rail + focus card with editable Target dates and a meeting-note textarea → wrap-up scorecard + ONE summary email per recipient (Requestor + IT Owner separately, deduped, cc pdl-plm-admin@sandisk.com). Every pending edit autosaves to a server-side draft (recoverable on next login). See "IT ENHANCEMENTS — MEETING MODE SUB-TAB" below for the full how-to.
- "My Enhancements" / "my enhancements" / "ECNs I own" / "what's on my plate" / "things assigned to me on IT Enhancements" / "bulk extend dates" / "extend UAT" / "extend go-live": My Enhancements sub-tab on the IT Enhancements page (second pill, shipped 2026-06-15). Scopes the grid to rows where you're the IT Owner. Row-selection checkboxes + bulk Extend Dates (+1 week, with preview) + bulk Add IT-Log Note.
- "high priority items" / "high priority ECNs" / "high-priority IT enhancements" / "priority 1 ECNs" / "urgent IT items" / "1-High items": the "High priority · no IT owner" focus pill inside IT Enhancements Meeting Mode filters the rail to ECNs with priority starting "1" AND no IT Owner assigned. The All Enhancements grid sorts/filters by the Priority column (1-High / 2-Med / 3-Low). The Urgent & Unassigned band tile on the All view counts the same population.
- "DRR" / "Document Review Record": Agile change object created when a document falls due for its yearly review. The IMS Review tab shows every DRR alongside its parent document, the current owner roster, and the queue status the toolkit has driven it to (Not Sent / Sent to DO / Sent to DM / In Flight / Closed / Need Help).
- "DCO" / "Document Change Order": the Agile change order the toolkit creates when a DO responds "Needs Change" on a DRR — carries the revised file + attestation PDF. The DCO and DRR are linked by a relationship rule that auto-closes the DRR when the DCO is Implemented.
- "Send to DO" / "Send for review" / "fire the DRR email" / "kick off the review cascade": click Send on a row in the IMS Review admin grid. The toolkit issues a one-shot signed token, generates the email body, attaches the current Agile file, and sends. Logs IMS_REVIEW_SEND.
- "DO response" / "Document Owner response" / "owner's options on the link": three buttons on the response page → ✅ No Change Needed (toolkit asks the DM to approve), 🔄 Needs Change (opens the 4-step DCO form), ❓ Need Help (DCC takes over). NO_CHANGE and NEEDS_CHANGE require an AD password + attest checkbox; NEED_HELP can include a file + note.
- "DM approval" / "Document Owner's Manager approval" / "DM step" / "second approval": after the DO confirms No Change, the toolkit emails the DO's manager (via LdapManagerLookup) and asks them to approve or send back. DM Approve → toolkit closes the DRR cascade (Pending → Submit → CCB). DM Send Back → another DO email round-trip.
- "auto-submit" / "auto submit" / "is the DCO submitted automatically?" / "is the DRR submitted automatically?": yes, by default. After the DCO is created with all data + attachments, the toolkit pushes the linked DRR Pending → Submit, then pushes the DCO Pending → Submitted. Exception: if the DRR submit fails (e.g. workflow validation), the DCO auto-submit is ABORTED (since Agile's ValidateDocument PX would reject it anyway), the DO gets a friendly "PLM IT is tracking" email, and pdl-plm-admin@sandisk.com gets a diagnostic with the SDK error chain. The DCO stays Pending in that case for DCC / IT to advance manually.
- "Reset" (per-row, on the IMS Review grid): wipes the queue state for that doc back to NOT_SENT. Full event history stays in queue.jsonl for the audit trail. Useful when a cascade gets stuck, when you want to re-test end-to-end, or after a deferred DCO submit. Available to anyone with the IMS Review tab grant (used to be admin-only).
- "Unlock" / "🔑 Unlock" / "lockout" / "invalid password" / "token lockout": after 5 wrong-password attempts on a response link, the toolkit locks that token (auto-clears after 15 min, OR an admin can click the per-row 🔑 Unlock button to clear it immediately). Same access as Reset — anyone with the IMS Review tab.
- "Reassign owner" / "edit owners" / "change Doc Owner" / "owner left" / "owner is no longer in AD": pencil ✎ on the Owner(s) cell on any row in the IMS Review grid OR the red "Assign owner" button in the Action column when no valid owner exists. Opens a modal with chip-based add/remove + Agile user search. Writes back to Agile via plm-agile-service. Triggers an email to the new owner with the file attached. Bulk reassign sends one email per doc. AS OF 2026-06-05 the reassign email no longer mentions that the previous owner has left SanDisk (HR-sensitive info per Vikas) — bare names only.
- "Owner history" / "Owner Audit" / "doc owner change history" / "who changed the doc owner" / "audit of owner changes" / "owner-change report": Owner history sub-tab INSIDE the IMS Dashboard (sub-tab strip just under the IMS Dashboard heading: "Documents" | "Owner history"). Reads Agile's ITEM_HISTORY table for IMS documents and shows every Document Owner change with old owners → new owners, when, and who instigated it. Three buckets: TOOLKIT (with user — green pill, names the AD user who clicked Save in the dashboard), TOOLKIT (legacy — blue pill, Agile actor=administrator but predates the marker; we know the toolkit did it, just not which AD user), DIRECT IN AGILE (amber pill, manual edit in Agile UI by a real user). Filters: Days dropdown (last 30/90/180/365), search box, source filter. Same access as IMS Dashboard — anyone with that tab grant sees Owner history automatically; no separate permission.
- "Toolkit history marker" / "logActionWOVersionChange" / "Owners updated via PLM Toolkit": history line the toolkit writes to Agile's ITEM_HISTORY whenever it updates a Doc Owner via the IMS Dashboard. Reads "Owners updated via PLM Toolkit IMS Dashboard by {AD user name}". Lets the Owner history sub-tab surface the real instigator (the AD user who clicked Save) instead of always showing Administrator. Added 2026-06-05.
- "Max overdue" / "max overdue years" / "hide old overdue" / "5 years filter": toolbar dropdown on the IMS Dashboard Documents view that caps how far INTO THE PAST a doc's next-review date is allowed to be before it's hidden. Options 1y / 2y / 5y (default) / 10y / Unlimited. Stops the 2010-era legacy heap of never-reviewed docs from drowning out the actionable backlog. Status line shows "hiding N docs overdue by more than Xy" when the filter trims anything. Added 2026-06-05.
- "Legacy docs" / "Legacy Documents" / "docs without a DRR": one of the segments on the IMS Dashboard segmented control. Shows documents the yearly-audit job hasn't created a DRR for yet. Has its own sub-filter pill row inside: All legacy / Valid owners / No valid owners. Useful for the historical baseline.
- "In flight" (IMS Dashboard segment): SENT_TO_DO + SENT_TO_DM + DO_NEEDS_CHANGE. As of 2026-06-05, DO_NEEDS_CHANGE counts as In flight (DCO is created but still in Submit/CCB until released) — it used to count as Closed, which was misleading.
- "Closed" (IMS Dashboard segment): only DM_APPROVED or CANCELLED. Means the DRR + DCO are truly done. Smaller than it was before because DO_NEEDS_CHANGE moved to In flight.
- "Needs owner" (IMS Dashboard segment): docs with a DRR where EVERY assigned Document Owner has left SanDisk (strict — partial-orphan rows where at least one owner is still active stay in Ready to send). The red banner "N documents need a new owner" now reflects this strict count.

FINDING A SPECIFIC ECN/ECO/MCO BY NUMBER:
- Easiest path: Change Reviews → Queue mode → leave analyst blank if you're admin (or type the owner's name), then type the change number into the column filter under "Change Number" (the filter row just below the headers). Click the row to open the signoff detail modal
- Alternate: Change History → enter the part number the change affects → the change number appears in the results table
- A change number alone (without an owner or part) cannot be looked up in any other tab today

RETURNING TO DEFAULT VIEW / CLEARING A SEARCH:
- Clear all column filters at once: click the small X icon in the first column of the filter row (the row just below the headers) on any data tab
- Reset BOM Explorer / Part Extract / Change History / Agile Lookup: clear the input box and click Search again, or just refresh the page
- Reset Change Reviews to your own queue: click the "Me" button in Queue mode (auto-loads your own changes)
- Return to the default landing tab from anywhere: click "Field Changes" in the top tab bar (or refresh the page — Field Changes is the default landing tab)
- Saved Searches button is the star icon (★) on supported tabs (Field Changes, BOM Explorer, Part Extract, Agile Lookup, Change History) — saved searches survive logouts and let you re-run a saved filter set in one click via "My Searches" in the nav bar

TAB 1: FIELD CHANGES (default tab)
- Shows field-level changes to Agile PLM items from the last 1 hour to 7 days
- Lookback selector: 1 hour, 1 day, 3 days, 5 days, 7 days (was "Days Back")
- Search filters: Field Name (comma=OR), Item Number (*=wildcard), Old Value Contains, New Value Contains, Changed By
- Net-change filter (toggle, on by default): hides changes that were reverted
- "When" column shows relative timestamps: "2m ago", "1h ago", "3h ago", "1d ago". Hover for full date. Auto-refreshes every 60 seconds.
- Copy button: small clipboard icon next to each item number — click to copy without expanding the row. Shows checkmark for 1 second.
- Click any row to expand and see inline diff (green=added, red=removed)
- Sort by clicking column headers. Default sort: newest first
- Clock icon (next to star): schedule recurring email reports (daily/weekly, 30-min intervals)
- Star icon: save search for re-use via "My Searches" in nav bar
- Export Excel / Email Me: download or email results as .xlsx (Excel still contains full timestamps, not relative)
- Yellow filter badge shows filtered row count AND unique item count
- Examples:
  - To find subcontractor changes: type "Subcon" in Field Name, click Search
  - To find changes to a specific part: type "A190-008600-8192G" in Item Number
  - To find new subcontractor assignments: put "C002,R010,C039" in New Value Contains
  - To see what a specific person changed: type their name like "Sessumes, Jimmy" in Changed By
  - Combine filters: Field Name = "PDA,PDM", New Value = "C002,R010,R020,C067"
  - Use "1 hour" lookback to check what just changed in the last hour
  - Click the clipboard icon next to an item number to copy it to your clipboard for pasting in Agile

TAB 2: BOM EXPLORER
- Explode (top-down): enter assembly number, see all components recursively (default depth 20)
- Implode (bottom-up): enter component, find all parent assemblies
- Results columns: Level, Parent, Component, Qty, Description, Item Type, Status, Rev, Lifecycle Phase, Product Line, Subcontractors, Build Plant, Ref Des, Find #, Path
- Path shows full traversal chain (e.g., "T002-TESSERA-0002 > A198-001237-1T00 > 54-07-07504")
- Implode: top-level parents get green "TOP" badge (e.g., SKU items like SDN1A-050G-1035K)
- Batch: comma-separated or upload .txt file (drag & drop supported, processed 3 at a time)
- 50K-row per-item cap and 500K-row total cap to prevent OOM. If hit, you'll be told which assemblies were skipped.
- Full Extract button: downloads complete BOM database as compressed CSV (~70MB, 6.5M rows, regenerated daily at 2 AM)
- BOM Notes Extract button: generates Excel of all BOMs with non-blank Notes (~39K BOMs). Auto-regenerated daily at 3 AM. Click button again to check progress. Rows with notes highlighted in amber. Files older than 7 days are auto-deleted.
- Large result sets (>10,000 rows) are capped on screen with a warning — use Export Excel for full data
- Column filters are debounced (300ms) to prevent slowdown on large datasets
- EXCEL EXPORT ROW-COUNT GUARD (shipped 2026-06-15): if a BOM export would produce more than 1,048,576 rows (Excel's hard per-sheet limit), it's rejected up front with a clear message — e.g. "BOM Where Used would produce 1,636,524 rows on the 'Top-Level Assemblies' sheet, exceeding Excel's 1,048,576-row limit. Narrow the input list or tighten filters (status, lifecycle, prefixes) and try again." Pre-flight happens BEFORE the workbook is allocated, so an oversize implode doesn't pin ~2 GB of results in heap before crashing mid-write (which was the actual cause of a 2026-06-15 prod heap-pressure alert). Both sheets are checked: main BOM rows + (in implode mode) the Top-Level Assemblies dedup count.
- Examples:
  - Explode T002-TESSERA-0002 to see all components in the Tessera assembly
  - Implode 56-35-00518 to see which assemblies use this ESD bag component
  - Use filter "!obs" in Status column to hide obsolete items
  - Use filter "sku" in Item Type to see only SKU-level parents

TAB 3: PART EXTRACT
- Look up part master data from item_extract table
- Column picker: dual-list to choose and reorder columns (shown with friendly Agile names like "Product Line" instead of "PRODUCTLINE")
- Only first 8 columns shown on screen; all columns in Excel export. Banner shows "Showing 8 of 25 columns"
- Search by item number (wildcards supported) and/or release date range
- Date format: MM-DD-YYYY consistently in UI and Excel
- Progress indicator shows row count during search ("Found 1,234 parts so far...")
- Drag and drop supported for file uploads
- Examples:
  - Search "SD*" to find all SanDisk parts
  - Search "A190*" to find all A190 assemblies
  - Search "SD*,A190*" with Released From = 04/08/2026 to find recently released parts

TAB 4: AGILE LOOKUP
- Queries live Agile PLM field values via Agile SDK API (proxied through a Java 8 microservice on port 8081)
- Two modes:
  (1) Upload Excel: Column A = item numbers, Row 1 headers = field names
  (2) Manual input: type item numbers + select fields via typeahead (1,250+ fields from Title Block, Page Two, Page Three). You can also upload a .txt/.csv file of item numbers in manual mode.
- Draggable field tags to reorder columns — drag the handle to rearrange
- "Field Not Present" (red italic) = field doesn't exist on that item type in Agile
- Blank cell = field exists but has no value
- Admin: "Update Field Names" link (visible only to admins) to upload Agile Classes Report CSV to refresh typeahead list
- Max 100 items per lookup. Max 100 MB file upload size.
- Fields are searched in order: Title Block, Page Two, Page Three, then direct
- Examples:

COMMON QUESTIONS (IMS Review):
- "Is the DCO auto-submitted?" → YES by default. The 4-step form's "Sign & submit" burns the token, creates the DCO fully populated, and the toolkit pushes both the DRR (Pending → Submit) and the DCO (Pending → Submitted) automatically. EXCEPTION: if the DRR push fails, the DCO submit is aborted cleanly and the DCO stays in Pending — the DO gets a friendly email, pdl-plm-admin gets a diagnostic with the SDK error chain. After PLM IT resolves the DRR-side blocker, DCC submits the DCO manually.
- "Is the DRR also submitted?" → YES, as part of the same cascade. For NEEDS_CHANGE: DRR.UpdateRequired=No + Pending → Submit (auto). For DM-APPROVED No-Change: DRR Pending → Submit → CCB (auto). DCC drives CCB → Closed (or via the relationship rule when the DCO is Implemented).
- "Where do the email attestation PDFs go?" → Both the DO PDF and the DM PDF are attached to the DRR via the SDK. For Needs-Change flows, the DO PDF is ALSO attached to the new DCO so the audit trail in Agile matches what the recipients received.
- "How do I cancel a cascade in flight?" → ✕ Cancel button on any SENT_TO_DO / SENT_TO_DM row. Burns the outstanding token, writes a CANCEL event to queue.jsonl, no Agile-side change.
- "What's the difference between Reset and Cancel?" → Cancel halts the IN-FLIGHT token (the email link stops working). Reset goes further — wipes the queue state for that doc back to NOT_SENT, ready for a fresh Send. Both preserve full history in queue.jsonl for audit.
- "An owner left SanDisk — what now?" → The grid shows ⊘ "left SanDisk" badge on their name + adds them to the NEEDS OWNER count. Click the ✎ pencil OR the 👤 Assign owner button to reassign. The new owner gets an email with the attachment + a prominent "Heads up: the previous owner Jane Doe is no longer at SanDisk" callout so they have context.
- "I'm getting 'invalid password' on the response link" → either (a) your AD password is wrong (5 attempts → 15-min lockout), or (b) you're using credentials of someone different from the intended recipient — the message now spells this out specifically and tells you to ask the right person or use your own AD username. Admins / DCC can clear the lockout immediately via the per-row 🔑 Unlock button.
- "Can I respond from someone else's email link?" → No. The token is bound to the recipient's email (or to all owners' emails for multi-DO docs). Trying to sign with another person's AD password returns an explicit "this link was sent to <Vikas>; your own credentials won't work — please ask them to handle this response" message.
- "Where does the LDAP status come from?" → LdapManagerLookup.checkUserStatus probes corporate AD (ldap://uls-ap-dcc72.corp.sandisk.com:636) per owner email. Results: ACTIVE / DISABLED / NOT_FOUND / UNKNOWN. Status is baked into the docs snapshot and refreshed on the hourly background rebuild; the request thread itself never waits on LDAP (added Jun 3, 2026 to fix a 9-minute first-load cost).
- "Why was the tab slow to load earlier?" → First cold call after a deploy used to take 100+ seconds (1,400 docs from Agile + ~1,800 LDAP probes). Now: the SQL pull persists to data/ims-review-docs-cache.json and survives restarts, LDAP enrichment runs on a daemon thread, and an hourly cron keeps it fresh. First call after a fresh deploy returns in ~SQL time (tens of seconds); owner badges fill in on the next refresh.
- "I clicked Send by accident" → Use ✕ Cancel right away on the row (the token won't be redeemable). If the recipient already opened the email, ask them to ignore it; the token expires after 30 days regardless. If the cascade is already mid-flight you can also use ⟲ Reset to wipe the state entirely.
- "Can non-admins use Reset / Unlock / Reassign?" → YES, as of Jun 3, 2026. Anyone with the IMS Review tab granted in User Management can use all three. Auto-granted DO/DM users (who only see their own card view, not the admin grid) still can't — they never see those buttons in the first place.
- "Is the Document Owner Cc'd on emails the toolkit sends?" → YES, as of Jun 3, 2026. Every IMS Review email has the DO either in To (when the email is addressed to them — DO response, owner reassign, DCO submit deferred user notice) or in Cc (DM ask, DCC Needs-Change, DCC Need-Help, DM-approved closure, DCO stakeholder notify, IT diagnostic). Cc-dedup is case-insensitive so the DO isn't doubled up when they're already in To.
- "Who shows up as the DCO Requestor?" → The Document Owner who signed the DCO form on the toolkit (e.g. Sessumes, Jimmy). If they aren't a valid Agile user (rare), the cell falls back to "Administrator" — Agile's session-user default. Before the Jun 3, 2026 fix, every auto-generated DCO showed "Administrator" because the toolkit wasn't setting the Requestor cell at all.
- "Who shows up as the DRR Requestor?" → On DM-Approve cascades, the DO who confirmed No Change (the original signer) — NOT the DM who approved. Earlier builds (before Jun 3, 2026) were overwriting the Requestor with the manager's name because the closeNoChange call was passing the DM's sAMAccount. Walks queue history backwards to pick the latest DO_RESPONSE_NO_CHANGE event so Send Back + re-confirm cycles still resolve correctly. ALSO on the Needs-Change auto-cascade (DCO creation flow), as of 2026-06-05 the DRR Requestor is stamped to the first valid Document Owner before the DRR Submit — fixes Agile's "Requestor cannot be Administrator" workflow rejection that previously left auto-cascade DRRs stuck in Pending.
- "Where do I see who changed the document owner?" / "Show me the doc owner history" / "Audit of owner changes" → Open the IMS Dashboard, click the "Owner history" sub-tab at the top. You'll see every Document Owner change recorded in Agile for IMS documents over the last N days (defaults to 90), with old → new owners, when, and who instigated it. Toolkit-driven changes show the AD user; manual Agile UI changes show "Direct in Agile" with the real user's name. Same access as IMS Dashboard — anyone who can see the dashboard sees this too, no separate permission needed.
- "Why does my owner change show as 'Toolkit (legacy)' instead of my name?" → The toolkit started writing a "Owners updated via PLM Toolkit by {AD user}" marker into Agile history on 2026-06-05. Owner changes from before that date have no marker — we know the toolkit did them (Agile actor = Administrator, only the toolkit uses that login) but we can't tell which AD user clicked Save. Those show as "Toolkit (legacy)" with instigator "(pre-marker; user unknown)". Changes from 2026-06-05 onward will show as "Toolkit" with the real AD user name.
- "Why does my recent change show as 'Direct in Agile'?" → It means the change wasn't done through the toolkit's IMS Dashboard — someone signed into Agile Web UI and edited the Document Owner cell there directly. Agile's actor column will be that user's real name (not Administrator). If you DID use the toolkit and it shows Direct in Agile, that's a bug worth reporting.
- "What's the difference between 'In Flight' and 'Closed' now?" → As of 2026-06-05, In Flight includes anything where the DCO is still being processed (SENT_TO_DO, SENT_TO_DM, AND DO_NEEDS_CHANGE — the latter means a DCO was created but is in Submit/CCB awaiting workflow). Closed is only DM_APPROVED (no DCO needed) or CANCELLED. Before this change, DO_NEEDS_CHANGE counted as Closed which made the funnel misleading.
- "What's 'Legacy docs' on the IMS Dashboard?" → The 6th segment on the segmented control. Shows IMS documents that the yearly-audit job hasn't created a DRR for yet. Has its own sub-filter pill row inside: "All legacy" / "Valid owners (N)" / "No valid owners (N)" so you can quickly see which legacy docs are still actionable vs which need an owner review first. Useful for the historical baseline.
- "Why are some old overdue docs hidden?" / "What's the Max overdue filter?" → New toolbar dropdown on the IMS Dashboard Documents view (added 2026-06-05). Default 5 years — hides docs whose next-review date is more than 5 years overdue, so the 2010-era legacy heap doesn't drown out the actionable backlog. Toggle the dropdown to 1y / 2y / 10y / Unlimited as needed. Status line shows "hiding N docs overdue by more than 5y" when the filter trims anything.
- "Why was the owner-reassign email less detailed today?" / "Why is the email not saying so-and-so left SanDisk?" → AS OF 2026-06-05 the email no longer mentions that the previous owner has left SanDisk. The red "Heads up: previous Document Owner is no longer at SanDisk" callout at the top and the "has left SanDisk" badge next to the replaced owner's name were both removed. That info is HR-sensitive and shouldn't be broadcast even to internal teammates. The Cc-vs-skip logic on the envelope still skips departed owners (no email bounce); that decision just doesn't leak into the body anymore. New owner still sees who they're replacing — just bare names.

VOICE COMMANDS / CHAT SHORTCUTS (added May 10, 2026):
- The chat inputs (helpInput in the Help sidebar AND askQuestion in Ask the AI) intercept your input BEFORE sending to the AI. If the text matches a known command, the action runs in-page and the AI is not called. If not, it falls through to the AI as before.
- This means: when the user types or speaks "show me the BOM Explorer tab", the chatbot does NOT lecture them on how to navigate — it just navigates them. Same for "go to BOM Race", "open ECN report", "I want to run a where used", etc.
- TOAST FEEDBACK: every recognized command flashes a small dark pill near the top of the screen ("Opening BOM Race…", "Exporting…", "Will export when the race finishes…"). Errors get a red pill ("No export button visible on this screen.").
- SUPPORTED VERBS:
  - Tab navigation: any of "go to" / "open" / "show me" / "take me to" / "switch to" / "navigate to" / "let's go to" / "I want to (see|open|view|run|do)" / "get me" / "bring me to" / "jump to" / "view" + a tab phrase. Also bare keywords work in non-English ("bom" alone navigates to BOM Explorer if no question word is present in the input).
  - Export: "export" / "download" / "save" + (it / this / the file / the files / the output / the rows / the data / the excel / nothing). Clicks every visible Export/Download button on the active screen, staggered 250ms apart so the browser allows multiple downloads.
  - Email / send: "email it" / "send to me" / "email me the output". Clicks the visible email/send button.
  - Race: "start the race" / "start standard race" / "start a quick race" / "start a stress race" → switchTab('bomrace') + apply preset + click Start.
  - Replay: "replay last" / "play it again" → switchTab('bomrace') + click Replay.
- MULTI-STEP CHAINS: the recognizer splits input on " and " / " then " / "," and runs each fragment. Example: "go to BOM Race, start a standard race, and export the output files" runs all three. The export step is smart — when the chain includes both start-race AND export, the export waits for race-done (MutationObserver on the scoreboard) before firing the download buttons.
- VOICE TYPO NORMALIZATION: speech-to-text often hears "BOM" as "bomb". The recognizer normalizes "bomb" → "bom" before matching, so "show me the bomb Explorer tab" routes correctly. Also handles "EC and" → "ECN", "S K U" → "SKU", "A I" → "AI".
- MULTI-LANGUAGE FALLBACK: if the strict English-prefix recognizer misses a command (e.g. user spoke in Malay or Mandarin), a soft keyword fallback scans the input for known tab nouns (BOM, race, ECN, etc.) — if found AND the input is short enough AND doesn't contain English question words ("what" / "how" / "why") AND has no "?", it navigates. Catches things like Malay "...butiran setiap bom" → BOM Explorer.
- WHEN ANSWERING "HOW DO I GO TO X?" QUESTIONS: prefer to NOT explain the navigation — the user's input itself probably already triggered the recognizer. If asked "how do I navigate to the BOM Race tab", the chatbot can say "Try saying or typing 'go to BOM Race' — I'll take you there directly." Don't lecture them step-by-step.

- Progress stepper: shows real-time progress as pill-shaped steps (Parse → Extract → Resolve source 3/14 → AI analysis) with elapsed timer
- Email when done: enter your email during analysis and get the full report delivered to your inbox when it finishes — you can close the tab
- Cancel button: abort a long-running analysis at any time
- History sidebar: shows your past analyses with exception name, input file, time ago, and resolution status (green/amber/red dot). Click any entry to reload the full results. "Clear all" button to delete history.
- Results display:
  - Root cause banner: extracted exception name, AI hypothesis, stats (traces/resolved/time)
  - Stack frames panel: each source ref with found/not-found/SDK status, source line preview
  - AI Analysis panel: full markdown analysis with severity rating, suggested fix, and explanation
  - Toggle raw stack trace view
  - Download report as .md file
  - Copy stack trace or analysis to clipboard
- Re-run button: go back to edit inputs and re-analyze
- New Analysis button: clear everything and start fresh
- Examples:
  - Paste a NullPointerException from an Agile PX hook — get the exact line, source code, and fix suggestion

  - "Why is the IT Owner / Status / Hours empty for some rows?" → IMS_REVIEW pulls these from agile.page_three (Owner from LIST53, Status from TEXT36, Hours from TEXT37). If the project owner hasn't filled them in on the ECN cover page, they're blank in the dashboard too.
  - "Why am I seeing more rows than the Excel?" → The dashboard's universe includes the saved-search "IT ECN's" branch (workflow=Review + IT request-classification) AND a "released in the past 7 days with IT Status" branch, to catch recent go-lives. The Excel snapshot might pre-date some of those releases.
  - "Where is the SNOW number column?" → SNOW number is not stored as an Agile attribute in this environment, so it's not in the dashboard. CRD and UAT Doc are also not in the grid (they're attachment references, not cell values).
  - "Why does Target UAT save take longer than other cells?" → The save opens a transient Agile SDK session under your identity, writes the cell, and closes the session. Each save = one transient session round-trip (~500ms typical). Batch saves run sequentially.

IT ENHANCEMENTS — MEETING MODE SUB-TAB (shipped 2026-06-15, the big one):
- WHAT IT IS: a structured surface for running the weekly IT-Enhancement backlog review with the room. Click the "Meeting Mode" pill (third sub-tab pill) to enter. The pill shows a small green badge with the number of notes captured this session.
- HOW TO USE — STEP BY STEP:
  1. Pick the people in the room from the "Reviewing" checklist dropdown (multi-select; busiest requestor first). Empty = all requestors.
  2. (Optional) Click a "Start with" focus pill to filter the list: "Overdue UAT / Go-Live" (red) · "Going live ≤ 7 days" (blue) · "High priority · no IT owner" (amber). Pill counts are scoped to the selected requestors. Click "Show all (N)" to clear.
  3. Walk the list. Click an item in the left rail to focus it; arrow keys (↑/↓/←/→) also navigate (ignored while you're typing). Focused-row stays in view as the rail auto-scrolls.
  4. On the right pane (focus card): edit Target UAT and Target Go-Live inline (they're marked ✎). Validation: Go-Live < UAT turns the field red with a "Needs fix" chip and is excluded from the batch until fixed. Risk badge + focus-pill counts recompute live as you edit dates.
  5. Type a meeting note in the textarea — it becomes a pending IT Log edit, stamped "[YYYY-MM-DD Your Name] note" and prepended to the existing IT Log.
  6. Click "Prev / Next" or use arrow keys to move on.
  7. When done, click "Wrap up & consolidate →" (enabled whenever there's at least one pending edit OR captured note).
- TO ANSWER "HOW DO I GO INTO HIGH-PRIORITY ITEMS?" — open Meeting Mode and click the "High priority · no IT owner" pill at the top. It filters the rail to ECNs with priority starting "1" (1-High) AND no IT Owner assigned. The count next to the pill tells you how many. To see all high-priority items regardless of ownership status, leave Meeting Mode and use the All Enhancements grid's priority column to sort or filter (priority column sorts by 1-High, 2-Med, 3-Low).
- LIST RAIL (left pane): each item shows index / ECN # / one-line proposal / status / risk-color left border (red=Overdue UAT, amber=Overdue Go-Live, blue=Approaching Go-Live). Right side has two dots: green = note captured · amber = pending edit (date or log change) · red = validation error. Independent — a row can show both, one, or neither. A color legend strip just above the panes documents this.
- FOCUS CARD (right pane): ECN link (opens in Agile) · risk badge · Edited/Needs-fix chip with row-level ↶ Undo · Requestor / IT Owner / IT Status / Priority / Target UAT (editable) / Target Go-Live (editable) / Hrs / Project meta grid · Problem (if any) · Proposal · LATEST UPDATE preview block (see below) · Meeting note textarea · Prev / Next.
- LATEST UPDATE PREVIEW (shipped 2026-06-15): below the Proposal, the focus card now shows "Latest update by <Name> · YYYY-MM-DD" with the previous IT Log entry inline. Author + date come from a structured fetch — first tries to parse Agile's inline bold author-band from the raw IT Log CLOB, then falls back to querying agile.CHANGE_HISTORY for the most recent "IT Log" modification. The body is the committed IT Log text (no need to expand a details element). For entries that lack any attribution metadata, the header just reads "Latest IT Log entry".
- UNDO AFFORDANCES (shipped 2026-06-15): every pending edit gets a ↶ undo control. Row-level ↶ Undo next to the Edited/Needs-fix chip clears every dirty entry on the ECN plus the captured note. Per-cell ↶ next to each pending date input clears just that cell. ↶ Discard note in the note hint area clears both the note and the IT Log pending edit. Nothing is sent to Agile until you click Save — Undo only touches the in-memory dirty map; saved Agile values are never affected.
- WRAP-UP SCORECARD: deterministic A/B/C/D/F grade computed from a weighted composite (Schedule health 40% · IT Owner coverage 20% · Target UAT set 15% · Target Go-Live set 15% · Effort/Hrs set 10%). IT Log population is intentionally NOT a criterion — many straightforward ECNs ship with no log entry and penalizing for that produces false bad-hygiene signals. Risk-count flags (overdue UAT, overdue Go-Live, stale Analysis, without IT Owner) appear below the metric bars. "To reach an A" list of prioritized recommendations is generated from the live gap analysis. Re-grade button recomputes after edits.
- CONSOLIDATED EMAILS (preview + send): each recipient gets ONE summary email listing every ECN that touches them — Krati with 3 affected ECNs gets ONE email listing all 3, not 3 separate emails. Same for the requestor. Sender Cc: pdl-plm-admin@sandisk.com (always). Subject: "PLM IT Enhancements — N ECNs updated by <Your Name>". Body: greeting → "<Your Name> updated N IT Enhancement(s) that you're involved with" → one card per ECN with hyperlinked ECN # + proposal context (truncated to 120 chars) + role line ("Your role: IT Owner · Requestor: X") + field-diff table (Field / Previous / New, green-highlighted) + meeting note (if any) → link to Agile.
- AUTO-SEND ON SAVE: when you click "Save N changes to Agile →" on the wrap-up screen, the toolkit saves to Agile first, then automatically fires the summary emails for every successfully-saved ECN. Toast: "Sent N summary emails (one per recipient, cc admin)". If some saves failed, the failed-edits roll into a separate admin-only failure summary email sent to pdl-plm-admin@sandisk.com with retry instructions; the failed entries stay in the dirty state so you can fix + Save again.
- AUTOSAVE + RECOVERY: every change you make in Meeting Mode (pending date edit or captured note) is debounced 1 second and POSTed to the server as a draft (stored at ./drafts/<your-loginid>-active.json). On next login the toolkit shows a recovery prompt: "Found unsaved meeting draft <Name>EditedOn<YYYY-MM-DD>.json — N pending edits, M notes — saved X minutes ago. Recover or Discard?" Recover restores everything and lands you back in Meeting Mode if there were notes. Discard wipes the draft. Drafts auto-delete server-side as soon as every edit lands in Agile via the save flow.
- PINNED-ROW POSITION: if you edit a Target date while a focus pill is active and the row no longer matches the pill (e.g. you fix an overdue date so it's no longer overdue), the row STAYS visible in the rail at its original position — so Next/Prev keep walking the list in the order you started. The badge + left-border still reflect the live state ("On track"), but the sort treats the row as if it still had its overdue kind.
- ECN HYPERLINKS: every ECN reference (rail items, focus card header, consolidation cards, email bodies) is hyperlinked to https://plm.sandisk.com/Agile/object/ECN/<number> and opens in a new tab.

WHY THIS TOOL EXISTS (build-vs-buy / strategic context for leadership questions):
- Built in-house by the SanDisk PLM IT team. The decision to build instead of buy was driven by three things:
  1. Deep Agile PLM coupling: SanDisk's Agile instance has highly customized field names, change workflows, lifecycle phases, AD-group mappings, and Oracle extract tables. Off-the-shelf PLM analytics products (e.g. Aras, Propel, Arena dashboards) require either expensive custom integration work or compromise on the SanDisk-specific data model
  2. Speed of iteration: in-house lets the PLM team ship daily fixes and new tabs (15+ tabs in roughly 12 months) directly in response to engineering, operations, quality, and CCB requests — no vendor backlog, no quarterly release cycles, no per-seat licensing for a population of ~1000 internal users
  3. Cost: the tool runs on a single Spring Boot JVM + the existing Oracle warehouse, no per-user license fees. Equivalent off-the-shelf BOM/change-history/cycle-time analytics tooling would run six figures annually for an enterprise of SanDisk's size
- Differentiator vs generic PLM analytics: tight Agile integration (live SDK queries, not just nightly extracts), embedded admin self-service (Utilities tab lets admins push their own scripts/reports without IT involvement), AI-assisted features (chatbot, debug stack-trace analysis, eval harness, returns-tracker AI clustering), and a one-click "email me" pattern across every report so users don't have to babysit long-running jobs
- ROI signal: tracked via the activity log (volume of LOGIN, *_SEARCH, *_LOOKUP, REPORT_RUN, etc. events). Replaces ~5 ad-hoc spreadsheets and a handful of standalone scripts that previously lived on individual laptops, plus eliminates several recurring manual data pulls the PLM team used to run for engineering and finance
- Audience: PLM IT, change analysts, BOM owners, manufacturing engineers, supplier-quality, finance/CCB. Built for the PLM team's own workflow first, then opened up tab-by-tab to other groups
