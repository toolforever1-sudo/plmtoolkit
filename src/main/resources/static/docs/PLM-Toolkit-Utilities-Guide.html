1. Overview

The Utilities tab in PLM Toolkit allows PLM admins to upload and run custom scripts directly from the browser. Scripts can be Python (.py), Java source (.java), or compiled JAR files (.jar). Each uploaded script becomes a "utility" that can be run on-demand with live output streaming, email notifications, and run history tracking.

The Utilities tab is organized into three groups:

GroupDescriptionExamples
Built-in ReportsReports engineered into the app by ITECN Change Order Report, What's New Digest
Uploaded ScriptsCustom scripts uploaded by adminsBOM Extract Delta, Change Creator
System DiagnosticsServer tools for admin useDownload Server Log, Activity Stats, Dry Run
Who can use this? Only members of the pdl-plm-admin AD group can upload, edit, and delete utilities. All admin users can run any utility. Non-admin users can only see utilities they have access to.

2. Supported Script Types

TypeExtensionHow it runsBest for
.py Python script python script.py [args] Data queries, Oracle DB scripts, file processing
.java Java source Compiled with javac, then java ClassName [args] Simple one-file Java tools
.jar Java archive java -cp file.jar;lib/*.jar MainClass [args] Complex Java apps with dependencies (Agile SDK, etc.)
Python path: The server uses the Python executable configured in application.properties as app.reports.python. On the production server this is D:\python\python.exe. Ensure your scripts are compatible with this Python version.

3. Uploading a New Plugin (3-Step Wizard)

Click the "Upload Script" button at the top of the Utilities tab. This opens a 3-step wizard:

1 File & Entry Point
  • Select your .py, .java, or .jar file
  • AI automatically analyzes the script (see Section 4)
  • For JARs with multiple main() methods: pick which class to run
  • Click Next when ready
2 Supporting Files
  • Upload config files (.properties, .xml, .json)
  • Upload input data files (.txt, .csv, .xlsx)
  • Upload dependency JARs (libraries needed on the classpath)
  • Properties files are auto-validated for path mismatches (see Section 14)
3 Details
  • Name: A human-friendly name (AI suggests one)
  • Description: What the script does (AI suggests this too)
  • CLI Arguments: Command-line flags (e.g., --verbose --output report.xlsx)
  • Environment Variables: Key-value pairs injected into the process environment
  • Click Upload to save

4. AI Script Analysis

When you select a file in Step 1, the system sends it to Claude AI for analysis. The AI reads the source code and detects:

DetectedWhat it findsExample
Environment variablesos.environ.get(), System.getenv()AGILE_DB_PASSWORD
Config properties.getProperty() callsemail.smtp.host=mailrelay.sandisk.com
Dependenciesimport statements (external packages)oracledb, Apache POI
CLI argumentsargparse, args[] patterns--out, --no-email, --dry-run
File argumentsArguments expecting file paths<properties_file> <items_file>
Entry pointsClasses with public static void maincom.sandisk.ccbdetails.BatchCreateMCO
Sensitive valuesKeys containing PASSWORD, SECRET, TOKENRendered as password fields with 🔒
Fallback: If AI is unavailable, a regex-based parser still detects env vars, imports, and argparse flags. The analysis badge shows AI or REGEX to indicate which was used.

JAR-specific analysis

For .jar files, the system:

  1. Reads META-INF/MANIFEST.MF for the Main-Class
  2. Lists all .java source files inside the JAR (if bundled)
  3. If .java files exist: AI reads them and runs full analysis
  4. If only .class files exist: shows "BYTECODE ONLY" with manual config prompts
  5. Detects all classes with main() methods as potential entry points

5. Environment Variables

Environment variables are key-value pairs injected into the script's process at runtime. They are not the same as Java .properties files — they are OS-level environment variables accessed via os.environ (Python) or System.getenv() (Java).

Example: Python script using env vars
import os

db_user = os.environ.get("AGILE_DB_USER", "agile")
db_pass = os.environ.get("AGILE_DB_PASSWORD")  # required
db_dsn  = os.environ.get("AGILE_DB_DSN", "uls-dp-oraagile.wdc.com:1521/AGILEPROD")

Env vars are stored in ./data/utilities/{id}/env.json on the server:

{
  "AGILE_DB_USER": "agile",
  "AGILE_DB_PASSWORD": "s3cret",
  "AGILE_DB_DSN": "uls-dp-oraagile.wdc.com:1521/AGILEPROD"
}

To edit env vars after upload: click ⋯ → Edit script & env on the utility row.

6. Supporting Files (Config & Input)

Supporting files are additional files your script needs to run — config files, input data, templates, etc. They are stored alongside the script in the utility's directory and can be swapped before each run.

TypeExtensionsExampleBehavior
Config.properties, .xml, .json, .cfg, .ini, .yamlmco_batch.propertiesRarely changes between runs
Input.txt, .csv, .xlsx, everything elseitems.txtOften swapped per run

Auto-passing as CLI arguments

If your script expects supporting files as command-line arguments and you haven't set CLI arguments explicitly, the system auto-passes all supporting files as positional arguments in order:

# If supporting files are: mco_batch.properties, inputitems.txt
# And CLI args field is empty, the command becomes:
java -cp SandiskCCBDetails.jar com.sandisk.ccbdetails.BatchCreateMCO mco_batch.properties inputitems.txt

Swapping files before a run

When you click "Run with files...", a drawer opens showing all stored files. You can:

  • Run with current files (no changes)
  • Replace any file by picking a new one from your computer
  • The replaced file becomes the new default for next time

Managing files after upload

In the Edit modal (⋯ → Edit script & env):

  • Each file has a ↓ download link to view the current version on the server
  • Each file has an × button to remove it
  • Pick a new file in the file chooser to replace it

7. Dependency JARs

Java utilities often need external libraries on the classpath. Dependency JARs are stored in a lib/ subdirectory and automatically added to the -cp classpath when the utility runs.

Common dependency JARs for PLM scripts
JARPurposeWhere to find it
AgileAPI.jarAgile PLM SDK/apps/agile/agile936/integration/sdk/lib/
SandiskTools936.jarSanDisk common Agile utilities/Users/vikasjindal/git/commoncodebase/
log4j-1.2.jarLoggingBundled in most projects
ojdbc8.jarOracle JDBC driverOracle installation
Version mismatch: The Agile SDK JAR version must match the Agile server version. Using AgileAPI936.jar against an Agile 9.3.6 server is correct; using it against 9.3.3 will cause NoSuchFieldError or NoSuchMethodError.

To add or replace dependency JARs: ⋯ → Edit script & env → Dependency JARs section.

8. JDK 1.8 for Agile SDK

The Agile SDK requires JDK 1.8. The server may have a newer default JDK (e.g., JDK 17). For utilities that use the Agile SDK, check the "Use JDK 1.8" checkbox in the Edit modal.

How it works: The checkbox tells the system to use the JDK 1.8 path configured in application.properties (app.reports.java8) instead of the default java on PATH. On the production server, this is:
C:\Program Files\Java\jdk1.8.0_162\bin\java.exe

The live stream will show which Java is being used:

⚙ Using custom Java: C:\Program Files\Java\jdk1.8.0_162\bin\java.exe
▶ C:\Program Files\Java\jdk1.8.0_162\bin\java.exe -cp SandiskCCBDetails.jar;lib\AgileAPI.jar ...

9. JAR Entry Points

A JAR file can contain multiple classes with public static void main(String[] args). During upload, the system detects all entry points and lets you pick which one to run.

Example: SandiskCCBDetails.jar — 3 entry points
ClassSourcePurpose
com.sandisk.ccbdetails.CreateReportFromTemplateSOURCEGenerates CCB status Excel report
com.sandisk.ccbdetails.BatchCreateMCOSOURCEBatch-creates MCOs from an items file
com.sandisk.ccbdetails.SampleSearchSOURCETest utility — runs an Agile query

The selected entry point is stored in reports.json and used at runtime: java -cp ... com.sandisk.ccbdetails.BatchCreateMCO

Classes with .java source bundled in the JAR show SOURCE — the AI can analyze them. Classes with only .class files show BYTECODE ONLY.

10. Running a Utility

Action buttons

ButtonWhen shownWhat it does
Run & email mePersonal utilitiesRuns the script and emails you the AI-analyzed summary + output file
Run with files...Utilities with supporting filesOpens the drawer to optionally swap files before running
Run & send to NBroadcast utilitiesOpens confirm modal, then sends to all recipients
Download nowDirect download utilitiesDownloads file immediately (e.g., server log)

What happens at runtime

  1. The system builds the command (Python/Java + classpath + args)
  2. Environment variables from env.json are injected
  3. The working directory is set to the utility's folder
  4. stdout/stderr are captured line-by-line for the live stream
  5. Output .xlsx files are detected and offered for download
  6. If "email me" was selected: AI analyzes the log and sends a summary email

13. Email Notifications

When "Email me the output" is selected, the system sends an AI-analyzed summary email after the utility completes (success or failure):

  • Subject: ✓ BOM Extract Delta · 92s · completed (or ✗ ... · failed)
  • KPI tiles: Status, Log lines, Output file info
  • AI callout: Claude reads the log and writes a 3-5 sentence summary of what worked, what failed, and next steps
  • Log preview: Last 15 lines of output inline in the email
  • Attachment: Output .xlsx file (if generated)

14. Properties File Path Validation

When you upload or replace a .properties file, the system automatically checks every value that looks like a file path:

  • Platform mismatch: Linux paths (/apps/agile/...) on a Windows server → suggests Windows equivalent
  • Path existence: Absolute paths that don't exist on the server
  • Auto-fix: Click "Fix all & re-upload" to automatically rewrite paths — the corrected file replaces the original
Example: Linux → Windows path correction
PropertyOriginal (Linux)Suggested (Windows)
template.input.path/apps/agile/oas101340/config/template.xlsxD:\agile\oas101340\config\template.xlsx
log.file.path/apps/agile/batch/logs/enhstatus.logD:\plm-toolkit\enhstatus.log

15. Server File Structure

Each utility is stored in its own directory under ./data/utilities/:

./data/
├── reports.json              ← all utility definitions
├── report-statuses.json      ← run history (persists across restarts)
└── utilities/
    ├── util-1776581452950/      ← BOM Extract Delta
    │   ├── bom_extract_delta.py  ← the script
    │   └── env.json              ← environment variables
    │
    └── util-1776589027892/      ← Change Creator
        ├── SandiskCCBDetails.jar  ← the JAR
        ├── mco_batch.properties   ← supporting config file
        ├── inputitems.txt         ← supporting input file
        ├── env.json               ← environment variables
        └── lib/
            ├── AgileAPI.jar       ← dependency JAR
            └── SandiskTools936.jar

16. Example: Python Script (BOM Extract Delta)

Script: bom_extract_delta.py

Compares Agile PLM's released-BOM view against CUSTOM_USER.BOM_EXTRACT and generates an Excel report of the deltas.

Step 1: Upload

  1. Click Upload Script → select bom_extract_delta.py
  2. AI detects: 7 env vars (AGILE_DB_USER, AGILE_DB_PASSWORD, AGILE_DB_DSN, SMTP_HOST, SMTP_PORT, MAIL_FROM, MAIL_TO), 2 dependencies (oracledb, openpyxl), 3 CLI flags (--out, --no-email, --dry-run)
  3. Click Next → no supporting files needed (uses env vars)
  4. Click Next → fill in env vars, set CLI args to --no-email, click Upload

Step 2: Run

  1. Click Run & email me
  2. Watch the live stream: connecting to Oracle, fetching data, writing Excel
  3. When complete: download the .xlsx output + receive AI-analyzed email

Step 3: Fix if needed

  • Wrong password? → ⋯ → Edit → update AGILE_DB_PASSWORD → Save
  • Wrong CLI args? → ⋯ → Edit → change CLI Arguments → Save

17. Example: JAR File (Change Creator)

Script: SandiskCCBDetails.jar

Batch-creates MCOs from an items file using the Agile SDK.

Step 1: Upload

  1. Click Upload Script → select SandiskCCBDetails.jar
  2. AI reads the bundled .java source files and detects 3 entry points
  3. Select com.sandisk.ccbdetails.BatchCreateMCO
  4. Click Next
  5. Upload supporting files:
    • mco_batch.properties — Agile credentials + config
    • inputitems.txt — list of item numbers to process
  6. Upload dependency JARs:
    • AgileAPI.jar — Agile SDK
    • SandiskTools936.jar — common utilities
  7. Click Next → set name, description → Upload

Step 2: Configure

  1. ⋯ → Edit → check ☑ Use JDK 1.8 (required for Agile SDK)
  2. Verify CLI args: mco_batch.properties inputitems.txt
  3. Save

Step 3: Run with different input

  1. Click Run with files...
  2. In the drawer: keep mco_batch.properties as-is
  3. Replace inputitems.txt with a new file for today's batch
  4. Check ☑ Email me the output
  5. Click Run now

18. Troubleshooting

ErrorCauseFix
NoClassDefFoundError: sandisk/agile/AgileChange Missing dependency JAR ⋯ → Edit → Add the JAR containing the missing class to Dependency JARs
NoSuchFieldError: APDM_LOSEDUPREDLINE_WARNING Wrong AgileAPI JAR version Replace AgileAPI.jar with the version matching your Agile server
ConnectException: t3 got an error or timed out Wrong Agile server URL or network issue Check agile.url in your properties file
Usage: java ... <properties_file> <items_file> CLI arguments not set ⋯ → Edit → set CLI Arguments to config.properties items.txt
Script exited with code 2 Python missing a package Install the package on the server: pip install oracledb
Linux paths in properties on Windows Properties file from wrong platform Upload the file → path validation auto-detects → click "Fix all"
Class not found for Java utilities Server using JDK 17, script needs JDK 1.8 ⋯ → Edit → check ☑ Use JDK 1.8
Output file not found (404 on download) Script ran with --dry-run or didn't generate output Check CLI args — remove --dry-run

19. Permissions & Ownership

ActionWho can do it
View utilitiesAll users (filtered by access)
Run a utilityAll admin users
Upload a new utilityAdmin users (pdl-plm-admin)
Edit a utility (env vars, CLI, files)Admin users
Delete a utilityOwner only — the admin who uploaded it
Owner-only delete: Even other admins cannot delete a utility they didn't upload. The Delete option is hidden from the ⋯ menu and the server rejects DELETE requests from non-owners.
