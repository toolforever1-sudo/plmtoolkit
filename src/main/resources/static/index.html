Quick Start Guide

Field Changes Tab

Search for field-level changes in Agile PLM items from the last 7 days. Use comma-separated values for OR logic. Click any row for an inline diff of old vs new values. The net-change filter (on by default) hides reverted changes.

Use the clock icon to schedule automatic email reports (daily or weekly).

BOM Explorer Tab

Explode: See all components of an assembly (top-down). Implode: See all parent assemblies (bottom-up), with top-level badges.

Results include lifecycle phase, product line, subcontractors, build plant, and BOM path. Use Full Extract for a complete BOM CSV or BOM Notes Extract for an Excel of all BOM notes.

Part Extract Tab

Look up part master data with friendly column names. Up to 8 columns shown on-screen; all selected columns included in exports. Dates displayed as MM-DD-YYYY.

Agile Lookup Tab

Look up live Agile field values via the SDK API. Two modes:

Excel Upload: Upload an .xlsx with item numbers in column A and field names in row 1.

Manual Input: Type field names with autocomplete (1,250+ fields) and enter item numbers directly. Searches Title Block, Page Two, and Page Three.

"Field Not Present" means the field does not exist on the item type (different from a blank value).

Change History Tab

View revision and change order history for items. Results are grouped by item number and include a lifecycle journey analysis with a color-coded timeline bar, phase duration table, and regression detection. Excel exports include a dedicated "Lifecycle Analysis" tab.

Saved Searches & Column Filters

Click the star icon on any tab to save a search for quick re-use. Load saved searches from the top navigation bar.

Column filter syntax: value = contains, !value = exclude, a,b = OR. Date columns have a checkbox dropdown.

Export & Email

Export Excel downloads results as .xlsx. Email Me sends the report to your company email. Large attachments (>5MB) are zipped automatically. Available on all tabs.

AI Help Chatbot

Click the floating "?" button (bottom-right corner) for AI-powered conversational help. The chatbot knows which tab you are on and gives tab-specific answers. Need to report a problem? Use Raise Issue in the help sidebar — it captures a screenshot automatically. Share your thoughts via the Feedback link in the nav bar.

Tips

All file uploads support drag and drop. Use * wildcards in item number fields. Your session auto-redirects to login if it expires.

📊 Source: AGILE.ITEM · PAGE_TWO/THREE · AGILE_FLEX · ATTACHMENT_FULL_MAP
ⓘ How this works — live equivalent of Camstar eVAR / TTMS, no overnight ETL lag

Camstar's eVAR (online stations) and TTMS (offline stations) both display controlled documents to operators based on the part being processed. Both pull from Agile via daily ETL jobs — ~14 hours of lag from the doc owner releasing a DCO until it shows up at the station.

This tab is the live equivalent: the same matching logic, run against agprod at query time. The instant a DCO is implemented and the doc has the right Page Three fields, the operator sees it here.

How a doc is matched to an operator's scan:

  1. Document Style = one of: WI · VAR · VIC · FPS · Guideline · Checklist · Drawing · Temp VAR · Offline VAR · Offline WI
  2. Latest Implemented DCO (Documents) or Implemented ECO (Parts)
  3. Matching (Product Group, Product, Spec) triple on Page Three
  4. The doc has at least one PDF attachment on that change

Common doc-owner gotcha:

On Page Three, you cannot mix ALL with a specific value in the same field. If Product = ALL, then Product can't also list a specific item. Same for Product Group and Spec. Violating this rule means the doc silently won't display on the floor — and that's the most common reason "where's my doc" tickets land in the queue.

Offline doc styles (Offline VAR / Offline WI) appear with a purple badge so operators can distinguish them from the eVAR (online) set at a glance.
