1. Logging In

Navigate to the PLM Toolkit URL in your browser. You will be presented with a login page.

  • Enter your corporate AD username (without the domain) and password.
  • You must be a member of the IT-APP-Agile-admin Active Directory group to access the tool.
  • If the corporate directory is temporarily unreachable, the tool will attempt to authenticate you using cached credentials from a previous successful login.

Access Request Workflow

If you are not yet a member of the required AD group, the login page shows a self-service Request Access form instead of an error message.

  1. Fill in your name and email address on the access request form.
  2. Submit the request. An email notification is sent to the PLM admin team.
  3. The tool automatically checks every 10 minutes whether your account has been added to the AD group.
  4. Once access is granted, you receive a confirmation email with a link to log in.
Tip: After submitting an access request, you do not need to keep the page open. You will receive an email once your access has been granted.

2. Field Changes Tab

This is the default tab. It lets you search for field-level changes made to Agile PLM items within the last 1 to 7 days. Data comes from the item_history table.

Net-Change Filter

Enabled by default. When on, changes that were subsequently reverted (value changed back to the original) are hidden. This lets you focus on the effective net changes. Toggle it off to see all intermediate changes.

Filter Badge (Unique Item Count)

When column filters are active, a yellow badge appears in the toolbar showing the number of unique items that match the current filters. This gives you a quick count of how many distinct items are affected, separate from the total row count.

Expanding Rows

Click any row in the results table to expand it. The expanded view shows:

  • Full item number, field name, revision, timestamp, and user
  • An inline diff highlighting what was added (green) and removed (red) between old and new values

Click the row again or press Esc to collapse all expanded rows.

Sorting

Click any column header with a sort icon to sort ascending or descending. The default sort is by timestamp (newest first).

3. BOM Explorer Tab

Explore bill-of-materials relationships in both directions. Data is queried live from the Oracle database.

Explode (Top-Down)

Enter an assembly number and click Explode. The tool recursively finds all components, sub-assemblies, and their components down to the specified depth (default 20 levels).

Implode (Bottom-Up)

Enter a component number and click Implode. The tool finds all parent assemblies that use the component, going upward through the BOM hierarchy.

Batch Lookups

You can look up multiple items at once in two ways:

  • Comma-separated: Type multiple item numbers in the input field separated by commas.
  • File upload: Upload a .txt or .csv file with one item number per line. Items are processed in parallel (3 at a time) for speed.

Max Depth

Control how many levels deep the BOM traversal goes. Options: 5, 10, 20 (default), or 50. Higher depths return more data but take longer.

Results Table

Item TypeItem classification (e.g., "A198-Card Retail Packaging")

All sortable columns can be clicked to sort ascending or descending. Use column filters to narrow results further.

Large Result Sets (10K Render Cap)

When a BOM query returns more than 10,000 rows, the table renders only the first 10,000 rows to keep the browser responsive. A banner indicates that results have been capped. The full dataset is still available via Export Excel or Email Me, which always include all rows regardless of the render limit.

Top-Level Badges (Implode)

When running an Implode search, components that are top-level assemblies (not used as a component in any other BOM) are marked with a badge. This helps identify finished goods or end-level products in the hierarchy.

BOM Notes Extract

The BOM Notes Extract button generates an Excel file containing all BOM relationships that have notes attached. This is an asynchronous operation — the extract is generated in the background and you are notified when it is ready for download.

Full BOM Extract

The Full Extract button (in the toolbar) downloads the complete BOM database extract as a compressed CSV file (.csv.zip). This is the entire BOM_EXTRACT table with all BOM relationships.

  • The extract is regenerated automatically every day at 2:00 AM.
  • If a file is available, clicking the button shows the file size and date, then starts the download.
  • If no file exists yet (e.g., on a fresh deployment), clicking the button triggers generation automatically. You'll see a message confirming generation has started.
  • If generation is already in progress, you'll see a message asking you to check back in a few minutes.
Note: The full extract file can be large (typically 50-100 MB compressed). The download time depends on your connection speed.

4. Part Extract Tab

Look up part master data from the item_extract table. This tab gives you full control over which columns to display.

Column Picker

The dual-list picker lets you choose and order columns. Column names are shown with friendly labels (e.g., "Product Line" instead of the raw database column name).

  • Available Fields (left): All columns you can add
  • Displayed Fields (right): Columns that will appear in the results, in order
  • Use the arrow buttons to move fields between lists
  • Use the up/down buttons to reorder displayed fields

On-Screen vs. Export Columns

To keep the on-screen table readable, a maximum of 8 columns are displayed at once. If you select more than 8 columns, the additional columns are still included in the Excel export and Email Me output, so you always get the full dataset in your exports.

Date Format

All date values are displayed consistently in MM-DD-YYYY format across the results table and exports.

Search Options

  • Item Number: Enter one or more part numbers (comma-separated) or use * wildcards. You can also drag and drop a .txt or .csv file onto the upload area.
  • Release Date Range: Filter by released date. You can combine this with an item number or use it alone to find all parts released in a date range.

Progress Indicator

During a search, a progress indicator shows the number of rows retrieved so far, giving you real-time feedback on large queries.

Tip: Leave the item number blank and set a date range to discover all parts released during a specific period.

5. Agile Lookup Tab

Look up live Agile PLM field values for a list of items using the Agile SDK API. Unlike the other tabs which query database extracts, this tab queries Agile directly for the most current data.

Mode 1: Excel Upload

  1. Prepare an Excel file (.xlsx) with the following format:
    • Column A: Item numbers (one per row, starting from row 2)
    • Row 1, columns B onwards: Field names you want to look up (e.g., Subcontractors, Actual Build Plant, Description)
  2. Upload the file using the file picker or drag and drop
  3. Click Look Up

Mode 2: Manual Input

Instead of uploading an Excel file, you can build a lookup manually:

  1. Switch to Manual Input mode
  2. Fields: Start typing a field name in the typeahead input. The autocomplete draws from a list of 1,250+ Agile field names. Select fields and they appear as draggable tags that you can reorder.
  3. Items: Enter item numbers directly (comma-separated) or upload a file with one item per line.
  4. Click Look Up

Field Search Scope

The tool searches for fields across Title Block, Page Two, and Page Three of each item. Results appear in a table matching your selected fields and items.

Limits

Maximum items per lookup is shown below the upload area (default: 100). If your file has more items, only the first 100 will be processed.

Handling Special Cases

  • "Field Not Present": Displayed when a field name does not exist on any page of the item type. This is different from a blank value, which means the field exists but has no data.
  • If a field name has a typo, the tool tries to warn you with a close match suggestion.
  • Results can be exported to Excel or emailed, just like other tabs.

Admin: Update Field Names

Administrators can upload a CSV file of Agile field names to update the typeahead autocomplete list. This is done via the Update Field Names button (visible only to admins).

Tip: The Agile Lookup tab connects to a separate Java 8 microservice. If you see connection errors, the Agile service may be down or restarting.

6. Change History Tab

View revision and change order history for Agile PLM items. Data comes from the AGILE schema, providing a complete audit trail of revisions, change orders, and lifecycle transitions.

Search Options

  • Item Number: Enter one or more item numbers (comma-separated) or upload a file with one item per line (drag and drop supported).
  • Date Filter: Use the date dropdown to limit results to a specific time period.

Results Table

Results are grouped by item number for easy scanning. Each row shows the revision, change order number, change type, release date, and associated details.

Lifecycle Journey Analysis

Each item in the results includes a visual lifecycle analysis that shows how the item moved through its lifecycle phases over time:

  • Color-coded timeline bar: A horizontal bar showing each lifecycle phase as a colored segment, proportional to the time spent in each phase.
  • Phase table: A detailed table listing each phase with start/end dates and duration displayed in a human-readable format (years, months, and days).
  • Regression detection: If an item moved backward in its lifecycle (e.g., from Production back to Prototype), the regression is highlighted so you can spot unusual transitions.

Excel Export with Lifecycle Analysis

When you export or email results from this tab, the Excel file includes a dedicated "Lifecycle Analysis" tab in addition to the raw change history data. This tab contains the phase-by-phase breakdown with durations for each item.

Tip: The lifecycle journey is especially useful for understanding how long items spend in each phase and for identifying items that regressed through lifecycle stages.

7. Utilities Tab

The Utilities tab (formerly "Reports") is a central place to run server-side scripts, built-in reports, and system diagnostics. Utilities are organized into three groups:

Three Groups

GroupDescription
Built-in ReportsPre-configured reports maintained by the PLM team (e.g., lifecycle aging, BOM integrity checks). These are always available and cannot be removed.
Uploaded ScriptsCustom Python, Java, or JAR scripts uploaded by PLM admins. These appear alongside built-in reports and run the same way.
System DiagnosticsHealth checks and diagnostic tools for the PLM Toolkit environment (e.g., Agile connectivity test, cache status).

Finding a Utility

Use the search bar at the top of the tab to filter utilities by name or description. The Mine / All toggle lets you switch between showing only utilities you have run before ("Mine") and the full list ("All").

Running a Utility

Each utility card shows a name, description, and one or more action buttons:

ButtonWhat It Does
Run & email meExecutes the utility on the server and emails you a summary with any output files attached. You can close the browser while it runs.
Run with files…Opens a drawer where you can upload supporting input files (e.g., a configuration file or a list of item numbers) before running. Not all utilities require this.
Download nowDownloads the output from the most recent run directly to your browser, without re-running the utility.

Viewing Run History

Click any utility row to expand it and see a history of past runs. Each history entry shows the run date, who ran it, the status (success or error), and links to download the output file and the server log for that run.

Access Control

Some utilities may be restricted to specific users. If you do not see a utility you expect, contact your PLM admin to be added to its allowed-users list. Admins can upload custom scripts to the Utilities tab, but the upload and configuration workflow is available only to admin users.

Tip: Use "Run & email me" for long-running utilities. The email arrives when execution completes, including an AI-generated summary of the run and any output files.

8. Data Compare Tab

A guided 5-step wizard that compares data from an uploaded Excel or CSV file against live Agile PLM data. This is useful for reconciling external system exports (e.g., SAP) with Agile.

Step-by-Step Workflow

  1. Upload: Upload your Excel (.xlsx) or CSV file
  2. Key Column: Select which column in your file contains the part/item number
  3. Map Columns: Map your file’s columns to Agile field names. The tool auto-suggests mappings using fuzzy matching — you can override any suggestion
  4. Filter Rows (Optional): Optionally filter which rows to include in the comparison
  5. Compare: Run the comparison and view results

Result Color Coding

ColorMeaning
GreenValues match between your file and Agile
RedValues differ
AmberPartial match (e.g., case or whitespace difference only)
GrayItem not found in Agile
Tip: The fuzzy column mapping works best when your Excel headers use names similar to Agile field names. You can always type a custom Agile field name if the auto-suggestion doesn’t match.

9. SKU Lookup Tab

Instant lookup of SKU records against a pre-loaded JSON cache (~48,000 SKUs). The cache is refreshed automatically every day at 2:00 AM.

Search Options

  • Item Number: Enter one or more item numbers (comma-separated, wildcards supported) or upload a .txt/.csv file

External Data Sources

Optionally join data from one or more External Data Sources (e.g., SAP exports uploaded by admins). For each selected source, a column-checkbox grid appears so you can pick which external columns to include. The result table shows Agile columns first, followed by each source’s columns (each source gets its own header color for easy identification).

Cache Refresh (Admin)

Admins see additional buttons for manual cache management:

  • Delta: Incremental refresh (~1-2 seconds)
  • Seed: Full rebuild (~30 seconds)
Tip: SKU Lookup uses a pre-built cache for instant results. If you need the very latest data that was just changed in Agile, ask an admin to run a Delta refresh first.

10. Extensions Tab (Admin Only)

Manage external data sources used by the SKU Lookup tab. This tab is visible only to members of the pdl-plm-admin AD group and designated extension contributors.

Adding a Data Source

  1. Upload an Excel file (.xlsx)
  2. Give the source a name (e.g., "SAP Master Data")
  3. Select the key column that contains item/part numbers (used to join with Agile data)
  4. Optionally set a schedule hour (0-23) for daily automatic refresh
  5. The cache is auto-generated on upload

Managing Sources

  • Generate: Rebuild the cache from the uploaded file
  • Schedule: Set or change the daily refresh hour
  • Remove: Delete the source entirely
Note: If you do not see this tab, you do not have admin or extension contributor access. Contact pdl-plm-admin@sandisk.com to request access.

10b. Shop-Floor Docs Tab

The operator-view replacement for the legacy SDSM nightly Windows batch. Type or scan a part / document number and instantly see every controlled PDF (Work Instruction, Visual Inspection Criteria, Drawing, Quality Notice, etc.) tied to the part’s latest released revision — live from agprod, no overnight wait. Designed to sit in front of a factory operator on the shop floor.

What the operator sees

  • Active Quality Notice banner at the top — lights up red when at least one QN deviation is in effect today (Status = Executed under the Quality Notice Workflow, with today between Effective From and Effective To). Lists the deviation number, description, and through-date.
  • Big input box — type a part number (e.g. 30-08-60003) or a document number (e.g. 06-05-WW-02-00002), or scan it with a barcode scanner. Press Enter or click Show Documents.
  • Spec / step-code chips appear above the results when the documents span multiple specs — click a chip to narrow to docs that apply to the operator’s current step code.
  • Result cards — one per controlled PDF. Each card shows a color-coded Document Style badge (WI = green, VIC = teal, Drawing = blue, Quality Notice = red, etc.), file name, part / Rev / DCO or ECO number, file size, Product Group, Product, and the spec chips that this PDF applies to.
  • View PDF opens a full-screen overlay with the PDF rendering inline (Chrome’s built-in viewer). Has a Download button and a Close button. Esc or click outside also closes.

What gets returned

  • Only PDFs whose Document Style is in the SDSM whitelist: WI / VAR / VIC / FPS / Guideline / Checklist / Drawing (plus Quality Notice for active deviations).
  • Each item is pinned to its latest Implemented DCO (Documents) or Implemented ECO (Parts). Older revisions are not shown.
  • Products with an OBS / OBS-SKU lifecycle are excluded from the displayed Product list.
  • Files containing "FAI" in the name and zero-byte files are skipped.

How the PDF is fetched

Two-tier resolution — the toolkit tries the local share first, then the Agile SDK fallback:

  1. Local share (tier 1): looks for the staged copy that the legacy SDSM batch left behind (e.g. D:\sdsm\Files\<part>_<rev>_<filename>.pdf). Filesystem read — fast, no SDK call.
  2. Agile SDK (tier 2): if the file isn’t on the local share, calls the plm-agile-service microservice which streams the bytes from the Agile File Vault.

The response header X-SDSM-Source: local or X-SDSM-Source: agile-sdk tells you which tier handled the request. (Open Chrome devtools → Network → click the /api/sdsm/file/… request to see headers.)

Visibility

Visible to everyone by default. Admins can hide it per-user via More → User Management; uncheck the Shop-Floor Docs row.

Vs. Work Instructions tab: Work Instructions searches the SanDisk PLM team’s general-purpose internal docs library (uploaded PPTX / PDF / DOCX). Shop-Floor Docs returns Agile-managed controlled documents tied to a specific part revision. Different audience, different content.

11. Saved Searches

You can save any search configuration for quick re-use later. Saved searches are available across the main search tabs: Field Changes, BOM Explorer, Part Extract, Agile Lookup, and Change History.

Saving a Search

  1. Fill in your search filters on any tab
  2. Click the ★ (star) button next to Clear
  3. Give the search a name (e.g., "Weekly Subcon Report")
  4. Click OK

The current values of all search fields are saved. You do not need to run the search first.

Loading a Saved Search

  1. Click ★ My Searches in the top navigation bar
  2. A dropdown shows all your saved searches
  3. Click a search to load it — the correct tab is selected, fields are populated, and the search runs automatically

Deleting a Saved Search

In the My Searches dropdown, click the X next to any saved search to delete it.

Tip: Saved searches are stored per user. Other users cannot see your saved searches.

12. Scheduled Reports

You can schedule the Field Changes search to run automatically and email you an Excel report on a recurring basis — without needing to log in to the tool.

Creating a Schedule

  1. On the Field Changes tab, fill in your desired search filters
  2. Click the 🕓 (clock) button next to the star
  3. The Schedule Report dialog opens, showing a summary of the search criteria that will be used
  4. Choose a frequency:
    • Daily: Report runs every day at the specified time
    • Weekly: Report runs once a week on the selected day at the specified time
  5. If Weekly, select a day of the week
  6. Select a time (available in 30-minute intervals from 12:00 AM to 11:30 PM)
  7. Click Save Schedule

The report is emailed to your corporate email address (the same one used for "Email Me").

How It Works

  • The scheduler checks for due reports every 5 minutes. Your report runs at the next check after the scheduled time.
  • The time is based on the server's timezone.
  • If the search returns 0 results, no email is sent (to avoid inbox noise). The run is logged on the server.
  • If the server is restarted, all schedules are preserved and will continue running.

Viewing and Deleting Schedules

When you open the Schedule Report dialog, the bottom section shows "Your Scheduled Reports" — a table listing all your active schedules with their search summary, frequency, and time. Click the X next to any schedule to delete it.

Email Format

The scheduled email is identical to what you receive when clicking "Email Me" manually:

  • Subject: PLM Field Changes Report - YYYY-MM-DD
  • Body: greeting, filter summary, record count
  • Attachment: Excel file (.xlsx), auto-compressed to .zip if over 5 MB
Note: Scheduling does not require saving the search first. The search parameters are captured at the moment you click Save Schedule. If you want to change the search criteria for a schedule, delete the old schedule and create a new one.

13. Column Filter Syntax

All result tables (Field Changes, BOM Explorer, Part Extract, Agile Lookup, Change History) have filter input boxes below the column headers. Filters are applied client-side with a 300ms debounce for smooth typing.

SyntaxBehaviorExample
valueShow rows where the column contains the textsubcon matches "Subcontractor"
!valueShow rows where the column does not contain the text!draft hides draft items
a,bShow rows containing a OR bC039,C002 matches either
!a,!bHide rows containing a AND b (both excluded)!test,!draft hides both
a,!bShow rows containing a but not breleased,!hold

Date Column Filter

Date columns have a special checkbox dropdown filter. Click the date button to open a list of all dates in the results. Check or uncheck specific dates to show/hide them. Use "All" and "None" shortcuts for quick selection. This is available on the "When" column in Field Changes, the Release Date column in Part Extract, and the Release Date column in Change History.

0-Dates Recovery

If the date filter accidentally deselects all dates (resulting in 0 visible rows), a red recovery button appears with the text "click to restore". Clicking it resets the date filter to show all dates again, recovering the full result set without re-running the search.

Tip: Click the X icon in the first filter column to clear all column filters at once.

14. Export and Email

Export Excel

Click Export Excel to download the current results as an .xlsx file. The export respects any active column filters, so you get exactly what you see on screen. Available on all tabs.

Email Me

Click Email Me to send the same Excel report to your company email address (the one associated with your AD account). The email includes:

  • A summary of your search criteria
  • The Excel file as an attachment

If the attachment exceeds 5 MB, it is automatically compressed into a .zip file before sending. Available on all tabs.

All emails are sent from PLM-Toolkit@sandisk.com.

BOM Notes Extract

The BOM Notes Extract on the BOM Explorer tab generates an Excel file of all BOM relationships with notes. This is an asynchronous extract — see the BOM Explorer section for details.

Full BOM Extract Download

The Full Extract button on the BOM Explorer tab downloads the entire BOM database as a compressed CSV. This is separate from the per-search Export Excel button. See the BOM Explorer section for details.

Change History with Lifecycle Analysis

Exports from the Change History tab include a dedicated "Lifecycle Analysis" tab in the Excel file, with phase durations and timeline data for each item. See the Change History section for details.

15. Help and Support

The PLM Toolkit includes a built-in AI-powered help assistant that can answer questions about any feature in the application.

Floating Help Button

A floating "?" button is always visible in the bottom-right corner of the screen. Click it to open the help sidebar.

AI Help Chatbot

The help sidebar opens a conversational chat interface. Type your question in plain English and the assistant will provide a relevant answer. The chatbot is tab-aware — it knows which tab you are currently viewing and tailors its answers accordingly. For example, asking "how do I export?" on the BOM Explorer tab will give you BOM-specific export instructions.

  • The conversation resets automatically when you switch tabs, so the assistant always starts fresh with the right context.
  • Click anywhere outside the help sidebar to close it.
  • If your session expires while the sidebar is open, the chatbot displays a friendly message with a link to log back in.

Raise Issue (with Screenshot)

If you encounter a problem, click the Raise Issue option in the help sidebar. The tool automatically captures a screenshot of your current screen and attaches it as a PNG image to the issue report. Describe the problem and submit — an email with your description and the screenshot is sent to the PLM admin team for investigation.

Tip: The AI chatbot can answer most questions about PLM Toolkit features instantly. Try asking "What does the net-change filter do?" or "How do I schedule a report?" before reaching out to the admin team.

Submitting Feedback

17. Keyboard Shortcuts and Tips

General Tips

  • Drag and drop: All file upload areas support drag and drop. Simply drag a file from your desktop onto the upload area.
  • The tool shows a progress bar for searches that take more than a few seconds.
  • If the database is temporarily offline, cached data is shown with a yellow banner indicating when the data was last refreshed.
  • Comma-separated values in search fields always mean OR logic (match any of the values).
  • Wildcard * is supported in item number fields across all tabs.
  • File uploads accept .txt and .csv files up to 5 MB with one item number per line.
  • All search results can be sorted by clicking column headers. Click again to reverse the sort direction.
  • Hover over truncated Description or BOM Notes cells to see the full text in a tooltip.
  • Your saved searches and scheduled reports are tied to your login. They persist across sessions and server restarts.
  • Session expiry: If your session times out, the tool automatically redirects you to the login page. Any unsaved work should be exported before stepping away.
  • This tool is currently in beta. Use the floating "?" button to ask the AI help chatbot any question about the tool, or use Raise Issue to report a problem with an automatic screenshot.
